    Stage 1 · RIAWELC specimen-level split · run riawelc_cpu

    A pipeline check, not a verdict on the method.

    An offline CPU run: ResNet-18 without ImageNet weights, 8,000 patches per epoch, patch head only (RIAWELC has no masks, so there is no IoU). Test split: 3,073 patches, 21 radiographs, 6 weld specimens. Numbers below are copied from the repository README.

    01

    No dataset has everything. RIAWELC has no masks, GDXray has 10 films and one class. SWRD (6 classes, polygons) is the main dataset from here.

    02

    The published split leaks. 108 of 109 radiographs sit in both train and test. Re-split by weld specimen (29 specimens).

    03

    A flatness shortcut. Patch std alone separates defect from no-defect with AUROC 0.91.

    04

    Tiny effective sample. Each test class occurs in only 2–4 specimens, so every recall carries a cluster-bootstrap CI.

    Per-class recall, test split

    Dot = recall, bar = 95 % cluster bootstrap CI over radiographs. Validation macro-F1 was 0.89 against 0.61 on test: specimen-to-specimen variance, not noise a single split can resolve.

    Recall vs. share of films sent to an inspector

    model (mutual information) random oracle

    Upper bound: the inspector is assumed to find every defect on referred films. AUC 0.832 model, 0.801 random, 0.875 oracle.

    Which uncertainty score flags wrong patches?

    AUROC of uncertainty vs. “patch has an error”. The pre-registered score (mutual information) is the weakest. Most errors are consistent uncertainty (aleatoric), not dropout disagreement. Changing the score based on this test observation would be test-set tuning; pick it on validation.

    Integration

    One endpoint between this page and a model.

    The repository has no inference server yet, and no trained checkpoint is committed. This is the contract the frontend speaks in “WeldSight API” mode. Implement it next to mc_predict in src/weldsight/eval/uncertainty.py.

    Request

    POST {API URL}/predict
Content-Type: multipart/form-data

image        file    radiograph (png / jpg / tif)
mc_samples   int     MC Dropout passes T (2–30)

    Response application/json

    {
  "width": 1024, "height": 384,
  "classes": ["porosity", "inclusion", "crack",
              "undercut", "lack_of_fusion",
              "lack_of_penetration"],
  "mask_png": "<base64>",      // R channel = class idx, 0 = background
  "maps": {                     // R channel 0–255 → 0–1, same size
    "pe": "<base64 png>",     // predictive entropy / ln 2
    "mi": "<base64 png>"      // mutual information, scaled
  },
  "defects": [{
    "cls": "crack",
    "prob": 0.91,
    "bbox": [x, y, w, h],
    "uncertainty": { "pe": 0.18, "mi": 0.05 }
  }]
}

    Notes

    • Class index 0 is background, defects are 1..K in the order of classes (same convention as data/sources.py).
    • The page ranks a film by the maximum defect uncertainty, matching the radiograph score used for the referral curve.
    • Enable CORS for the page origin, or serve web/ from the same FastAPI app via StaticFiles.
    • Pixel-level maps are not stored by mc_predict today (it keeps memory O(N)). The server needs to return them for the one image it is given.
    • Serve the page locally: python -m http.server -d web 8080
