## Запуск (≈5 минут, если данные уже подготовлены)

```bash
uv sync --extra dev --extra serve
```

```bash
uv run weldsight-prepare --config configs/experiment/riawelc_baseline.yaml --download
```

Для распаковки нужен настоящий `unrar` (`apt-get install unrar`). `unrar-free` и 7-Zip из Debian
не читают этот RAR5 и молча распаковывают пустые файлы.

```bash
cd frontend && npm ci && npm run build && cd ..
```

```bash
uv run weldsight-serve --run runs/<riawelc_cpu_...> --static frontend/dist
```

Открыть http://127.0.0.1:8000. Если обученного прогона нет:
`uv run weldsight-train --config configs/experiment/riawelc_cpu.yaml` (≈40 мин на 4 ядрах CPU)
или `uv run weldsight-serve --stub --static frontend/dist` (эвристика, не модель, и интерфейс это
пишет прямо).

## Сценарий показа (10–12 минут)

1. **Вкладка Dataset → Train.** «Вот на чём модель училась: 15 560 патчей из 17 образцов шва». Пройти
   по фильтрам: трещина, пористость, непровар, без дефекта. Показать, что патчи «без дефекта»
   заметно глаже. Это шорткат, который мы нашли: одно СКО отделяет их с AUROC 0.91.
2. **Dataset → Test.** «А эти 6 образцов модель не видела вообще. Сплит по образцам, не по
   патчам. В официальном сплите 108 из 109 снимков были и там, и там».
3. **Клик по патчу трещины** → Inspect. Справа: вероятность по каждому классу, ± разброс по 10
   проходам MC Dropout, истинная метка, match/mismatch, неуверенность. Решение «отправить
   инспектору» срабатывает, когда неуверенность выше порога.
4. **Найти ошибку модели** (в test есть много непровара, у него recall 19 %) и показать, что на
   ней неуверенность высокая. Это и есть смысл оценки неуверенности: модель сама говорит, где ей
   нельзя верить.
5. **Вкладка Stage 1 results**: recall с доверительными интервалами и кривая передачи инспектору.
6. **Честная часть**: что модель на RIAWELC умеет только классифицировать патчи (масок нет), а
   сегментация будет на SWRD, и почему мы на нём ещё не обучились (см. ниже).

## Чего нет, и это нужно сказать самим

- **Нет сегментации.** В RIAWELC нет масок, поэтому на вкладке Inspect одна рамка на патч, а не
  контур дефекта. В интерфейсе так и написано.
- **Нет обучения на SWRD.** Данные подготовлены (подмножество v1, `data_version aa609714f665f727`),
  редкие классы зафиксированы, а GPU-прогон в Colab ещё не сделан. Узкое место — квота Google Drive
  на 116-гигабайтный архив (отсюда весь код с HTTP Range) и Colab-GPU.
- **Этапы 2–3 (copy-paste и диффузия) не начаты.** Протокол сравнения записан заранее в `ROADMAP.md`.
- **Один сплит и один сид.** Разрыв val→test (macro-F1 0.89 → 0.61) показывает, что на 6 образцах
  оценка шумная; дальше нужна k-fold кросс-валидация по образцам (`weldsight-split-audit` уже
  считает раскладку).

## Вероятные вопросы

- *Почему не accuracy?* Есть шорткат «гладкий патч = без дефекта», и accuracy его награждает.
  Смотрим recall по классам с ДИ.
- *Почему ДИ такие широкие?* В test на класс 2–4 образца. Bootstrap идёт по снимкам, а не по
  патчам: патчи одного снимка не независимы.
- *Почему MC Dropout, а не ансамбль?* Дёшево: один encoder-проход и T проходов головы. Ансамбль —
  кандидат на сравнение.
- *Почему меняете метрику неуверенности?* Не меняем по test. Правило выбора на val записано
  и закоммичено до расчёта (`docs/UNCERTAINTY_SELECTION.md`); результат ниже.
